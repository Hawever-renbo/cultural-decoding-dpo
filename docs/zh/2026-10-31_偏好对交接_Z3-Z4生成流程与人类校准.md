## 1. 偏好对现在怎么造（Z4）

| 步 | 做什么 | 代码与提示词（线目录下） |
|---|---|---|
| 单元 | 一篇论文里同一分析小节的 3–8 条引语，加研究背景。来自 U3 候选，Sonnet 复核 | `u3.py`、`z4.py select / units` |
| 文章卡 | 从论文里抽研究情境、作者解读这些引语的原句（「读法」）。每条读法按抽象程度标一级、二级或三级 | `p2.py` 的流程，`lib/prompts7.py`（第七版，R2–R4 校准，D-165 放行） |
| rubric | 每单元一份。读法项写「这层意思写到没有」，带 question / pass_if / fail_if；克制项写「不过度解读、不外推」；另有反思项 | 同上 |
| 初稿 | 模型只看情境与引语，写整份三级编码：开放码、范畴、关系、核心、故事线、备忘录。**看不到作者读法** | `z1.py`（Haiku low 或 Sonnet medium） |
| 挑目标 | 初稿在哪条读法项上判 FAIL，就拿那条读法造对。每单元至多 3 对，三级每篇论文 1 对 | `z4.py plan` |
| 较优 | 初稿加作者的一条读法，**只改一个元素**：一级改开放码，二级改范畴名或关系，三级改核心。拿到目标读法项与全部克制项，一次写 4 份候选，由评委逐项判，取过线的一份 | `lib/prompts_z4.py` 的 SYS_WIN、SYS_PICK |
| 较劣 | 同一份初稿、同一处，另一次调用写「读浅」的版本：准确、通顺、具体，只是不做那条读法。同样拿到目标读法项与克制项（两侧对称，D-177、D-189）。篇幅与较优相近，不得与初稿逐字相同 | SYS_LOSE |
| 评委 | Opus low，两侧放进同一次调用，按每单元 rubric 逐条判，外加质量项：Q1 准确、不丢信息；Q2 清楚通顺；三级另加 Q3，核心要由这份编码撑住 | SYS_JUDGE |
| 干净 | 程序闸、篇幅、目标项较优过而较劣不过、没有一项较劣过而较优不过、两侧都过质量项 | `z4.py build` |
| 上站 | 审核站（Vercel `gt-pair-review`）。专家先盲选 A、B 或「差不多」，揭晓后答「对 / 部分对 / 不对」，可写理由 | `web/build_pairs.py --source z4` |

**Z3 与 Z4 的差别**：
- Z3 写较优时没拿 rubric，较劣拿了目标项。用户指出这是漂移（D-176）。
- Z4 改为两侧对称拿 rubric，并加了写法要求（STYLE）、较优 4 选 1、质量项、三级只比核心。

## 4. 待解决的问题（请审查的 agent 重点看）

这些都没有定，改方案前要先问用户。

1. **较优该是什么？** 用户的几次表态方向并不完全一致，要请用户定：
   - R2（10-19）：用户说作者读法可能读多了，原话是「basic requirements for a relationship 是否有过度解读，在这里不能完全看出来」（`prereg/R2_结果.md` B4）。
   - R3（10-19）：用户说「not being touched 引文里没有，但是模型要是能文化解码到这一步就厉害了」，也就是引语里没有、但能从材料里解码出来，正是想要的能力（`prereg/R3_结果.md` F）。
   - D-177：较优「以作者的为基础」，按专家一的 taste 对齐。
   - D-198：专家一是金标，而专家一这次大多不认作者的推断。

   主会话提过三条路，各有冲突：
   - **只用引语撑得住的作者读法**：与 R3 的表态、D-177 可能相左；能用的读法会少很多。
   - **把支撑读法的材料放进输入**：如果放的是作者的论述，就碰到 spec 与环境分开（D-146）、作者读法不给写初稿的模型（D-148、D-149），以及现状待定第 5 条（训练输入比终评多两项）。
   - **较优改写成「有据的深一层」**，不再照搬作者原句：会动到 D-148「较优取自作者」的核心设计。
2. **rubric 给哪一侧？** 用户问过「要不要考虑 rubric 只给较优这边」。现有数据：

   | 轮 | rubric 给哪侧 | 专家一选中较优（一、二级） |
   |---|---|---|
   | Z3 | 只给较劣（D-176 指出的不对称） | 0.62 |
   | Z4 | 两侧都给 | 0.35 |
   | — | 只给较优 | 没试过 |

   **这两行之间有混淆**：除了 rubric，还改了写法要求、4 选 1、质量项、一级来源，单元和论文也不同，不能把差别算到 rubric 头上。

   主会话的看法：只给较优，较劣会变弱，可能会混进写法的混淆（V10 H3 要防的）。Pan 等（2025）指出较优质量才起主导作用。不过 Z3 的标签数据显示，较劣写得别扭，并没有让专家一转向较优。这一条由用户定。
3. **评委怎么才能贴近专家一？** 可以用专家一这 21 条理由（加 Z3 的 24 条），补写判分项，例如「读法能否从页面上的引语看出依据」。补写后，要在没参与调参的对上量；还要与第 1 条的方向一致。
4. **三级怎么做？** 作者的核心撑不住（Q3），观察组里专家一也多选了较劣。用户说「看效果再定」。
5. **一级「标签与证据对不上」**：较优的标签说的意思，所引那句原话里看不出。主会话读的时候挡掉过，专家一也指出过。
6. **同一处里较优与较劣的信息量不对等**：较优＝初稿那一处加作者读法，较劣是重写的，可能丢掉初稿原有的内容。W14809 里，较优保留了初稿的最后一句，较劣删了，专家一说较优那句是「额外信息」。

- 模型调用只走 Claude Code CLI（`claude -p`，订阅额度），不调 deepseek 等按量付费的 API（D-146）。用户之后会配 Anthropic API key，那时另记 D 号。
- 测试集（`research/datasets/test-set/`）任何生成都不得读取；排除清单每段开头重算（V10 §4.3.4）。
- `out/deviation.md` 只许追加，新决定记下一个 D 号。
- 每轮先写预注册、冻结（`tools/freeze.py`），再调用模型。冻结件不改，确需改时带说明重冻。
- 审核者在盲选之前，看不到模型一侧的判断（自检 C13）。
- 专家口令、`web/data/experts.json`、`web/secrets/` 不打印、不外传。`pairs.real*.json` 含论文摘录，不入库。
- 偏好对都标 `pilot_*`，是试点，不是训练数据；各轮的数不相加，也不与 V10 的 540、158、50 相加。
- 自检：`python3 外部文档/后训练转向/research/合成数据线/90_自检.py`，全绿且阳性对照全红才算过。
